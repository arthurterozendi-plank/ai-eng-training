Flash Session — AI-34 · TalentScout domain model

~60 seconds · Plank harness
What & why

TalentScout gets a database: seven tables, migrations and 90 seeded applications.

There was no persistence at all. A recruiter reconstructed a pipeline from an inbox — nothing queryable, nothing chartable, nothing an agent could be handed.

  • Day 5 queries it over MCP, Day 9 charts it, Day 13 indexes its free text, Day 17 writes extractions into it, Day 18 gates those writes.
  • pipeline_stages · jobs · candidates · applications · application_stage_transitions · interviews · notes
  • Ticket: AI-34 — "Model jobs, candidates and applications in Postgres for recruiters tracking a pipeline"
The decision

applications.stage is a text FK into a seeded lookup table — not a pg enum.

We chose

A pipeline_stages table seeded by migration, referenced by applications.stage, coexisting with an application_stage_transitions history table.

Order and labels stay data, so Day 9 can sort a funnel chart on position and a recruiter can rename a stage. The projection column keeps every dashboard query single-table and makes "every application has a stage" a NOT NULL guarantee.

We rejected

A pg enum. Values can never be dropped, ALTER TYPE … ADD VALUE cannot run inside a transaction, and the ordering Day 9 needs would be locked in the type rather than queryable.

Deriving the stage from history alone. A DISTINCT ON on every read — and an application with no transitions would have no stage at all.

Verified & risk

How we know it works

watch: no live DB — run db:migrate/db:seed by hand watch: RLS on, zero policies — AI-43 needs owner creds watch: 3 seed-realism follow-ups
Per-field confidence as versioned jsonb

An envelope { schemaVersion, model, extractedAt, fields } guarded by both a zod schema and a jsonb_exists CHECK. Rejected: per-field confidence columns — Day 17 will change the shape.

ON DELETE RESTRICT on both application FKs

Deleting a job that has applications is refused, not cascaded — and the same for candidates, which AC 6 does not even require. Rejected: cascade, and a "live applications only" rule a plain FK cannot express.

notes attaches via num_nonnulls(…) = 1

Three nullable FKs plus a check, so a note is bound to exactly one job, candidate or application. Rejected: a polymorphic entity_type/entity_id pair, which has no referential integrity at all.

The seed ships no row-removing code path

It refuses on any populated target table and cannot empty one — not even behind a flag. Rejected: a guarded reset, because a guarded truncate pointed at the hosted project is still a truncate.

Slice 1 — Tooling and env plumbing

Adds drizzle-orm (dependency) plus drizzle-kit/drizzle-zod/postgres/tsx (devDependencies), a credential-less drizzle.config.ts, the five db:* scripts, and the two Postgres URLs. The whole ticket is verifiable offline because of what this slice does not configure.

Slice 2 — Enums, pipeline_stages, jobs, candidates

The ordered stage lookup table plus the two root entities. Every table carries .enableRLS() and exports its $inferSelect/$inferInsert types — AC 5 has no hand-written row type anywhere in the change.

Slice 3 — applications + application_stage_transitions

The core of the ticket: AC 2 (exactly one job and one candidate), AC 3 (timestamped transitions), AC 4 (per-field confidence) and AC 6 (deletion refused, not cascaded) all land here, enforced by the database rather than by convention.

Slice 4 — interviews + notes

The two free-text tables Day 13's RAG corpus is built from. notes is the one place a polymorphic column was seriously tempting, and the one place it was refused.

Slice 5 — Relations

Roughly thirty declarative lines with no runtime cost, so AI-43 and AI-63 write typed with: {…} queries instead of hand-rolled joins. Their location is the decision, not their existence.

Slice 6 — Migrations

0000 is generated DDL — this slice edits no schema file. 0001 is hand-written and carries exactly what drizzle cannot express: reference rows, a deferrable constraint, and updated_at maintenance.

Slice 7 — The seed dataset

8 jobs, 60 candidates, 90 applications, 293 transitions, 40 interviews, 120 notes, 12 extraction payloads and ~73k characters of hand-authored prose — pure, deterministic, and no faker, because the corpus is the point of the free-text columns.

Slice 8 — Runners, seed guard and docs

Both runners connect over DIRECT_DATABASE_URL — Supabase's transaction pooler breaks DDL and the migrator's advisory locks — and both short-circuit on --dry-run before importing @/env or postgres.
