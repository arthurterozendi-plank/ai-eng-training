What & why

The Week 2 CLI gets its own repository, scaffolded and provably runnable.

Day 4 of the programme practises switching between workspaces. That is only a real exercise if the two are genuinely different codebases — so the second one had to exist, and had to be separate.

  • Day 6 builds the chatbot in it; Day 7 reuses it as the tool sandbox.
  • Blocks AI-39 and AI-48.
  • Ticket: AI-41
The decision

A separate repository, not apps/cli

We chose

../talentscout-cli — its own lockfile, lint rules, TypeScript config and CLAUDE.md. The shared config packages are private + workspace:*, so they were unreachable across a repo boundary anyway.

We rejected

apps/cli — free @talentscout/db access and one pnpm check, but an inherited root CLAUDE.md makes “its own conventions, not a copy” unsatisfiable, and Day 4 would be exercising a directory change.

The decision, recorded

The README argued the monorepo exists because every later surface shares the schema and the lint rules. The CLI does not — so the rationale needed qualifying, not extending.

Two settings that look like noise

Both files exist for exactly one line each, and deleting either breaks the build. The reviewer deleted both to confirm they were not cargo-culted.

The run() / main() seam

run(argv) decides what to print, on which stream, with which exit code, and performs no I/O. main.ts is the only module that touches process. That seam is what AI-48 will test a conversation loop against.

Its own conventions

AC 2 asks for a CLAUDE.md that is not a copy of the web app's. It is checked mechanically in both directions: zero web-app rules present, four repo-specific rules present.

Proof, not assertion

A smoke test that still passes with the feature deleted is worse than no test. This one was mutated three ways and went red each time.
